# 发布 P5：签名与公证操作手册

> 状态（2026-07-27）：证书之前的全部脚手架已就绪——entitlements、hardenedRuntime
> 配置、NSIS 安装器、`release.yml` 发布流水线（签名按 secrets 自动降级）。
> 拿到证书后只需往仓库塞 secrets，不需要改任何代码。

## 一、现在就能用的（无证书）

```bash
# 手动触发发布构建（未签名 dmg + nsis 安装包，artifact 保留 3 天）
gh workflow run release.yml
# 或推标签，额外创建 Release 草稿并附安装包
git tag v0.11.0 && git push origin v0.11.0
```

未签名安装包完全可用，只是首次打开需要：macOS 右键 → 打开（或
`xattr -dr com.apple.quarantine`）；Windows SmartScreen 点「仍要运行」。

## 二、macOS 正式签名 + 公证（需 Apple Developer Program，$99/年）

1. 注册 [Apple Developer Program](https://developer.apple.com/programs/)
2. 在 developer.apple.com → Certificates 创建 **Developer ID Application** 证书，
   下载后导入钥匙串，再导出为 `.p12`（设一个密码）
3. 生成 App 专用密码：appleid.apple.com → 登录与安全 → App 专用密码
4. 配置仓库 secrets（Settings → Secrets and variables → Actions）：

| secret | 内容 |
|---|---|
| `MAC_CERT_P12` | `.p12` 文件的 base64（`base64 -i cert.p12 \| pbcopy`）|
| `MAC_CERT_PASSWORD` | 导出 `.p12` 时设的密码 |
| `APPLE_ID` | Apple ID 邮箱 |
| `APPLE_APP_SPECIFIC_PASSWORD` | 第 3 步的 App 专用密码 |
| `APPLE_TEAM_ID` | developer.apple.com → Membership 里的 Team ID |

5. 重跑 `release.yml` —— 检测到证书后自动走「签名 + 公证」分支

**本地签名**（可选）：`CSC_LINK=/path/cert.p12 CSC_KEY_PASSWORD=xx APPLE_ID=... APPLE_APP_SPECIFIC_PASSWORD=... APPLE_TEAM_ID=... npx electron-builder --mac -c.mac.notarize=true`

注意：内嵌引擎（PyInstaller 产物，含 torch 数百个 dylib）会被 electron-builder
深度签名，公证时长可能到 10–30 分钟；entitlements 已按此场景配置
（disable-library-validation 等，见 `build/entitlements.mac.plist`）。

## 三、Windows 代码签名（可选，消 SmartScreen 警告）

标准代码签名证书（OV，约 $70–200/年，Sectigo/SSL.com 等）或 EV 证书
（即时信誉，但需硬件 key，CI 集成复杂）。OV 证书拿到 `.pfx` 后：

| secret | 内容 |
|---|---|
| `WIN_CERT_PFX` | `.pfx` 文件的 base64 |
| `WIN_CERT_PASSWORD` | 证书密码 |

SmartScreen 信誉需要下载量积累，签名后初期仍可能提示，属正常。

## 四、验证清单（拿到证书后跑一遍）

- [ ] `spctl -a -vv "Stem Studio.app"` → `accepted, source=Notarized Developer ID`
- [ ] `codesign -dv --verbose=2` 确认 hardened runtime + entitlements
- [ ] 全新 mac 用户账户直接双击可开（无右键仪式）
- [ ] 打开后完整跑一次分离（引擎在签名后仍正常 spawn——entitlements 验证点）
- [ ] Windows：属性 → 数字签名标签页存在；安装 → 运行 → 分离一次
